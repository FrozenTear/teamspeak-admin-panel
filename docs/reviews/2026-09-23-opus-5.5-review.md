## High

### H1. Moderation API ignores per-server grants

- **Where:** `routes/moderation/{cases,actions,complaints,automod,appeals,reports,notes,history}.rs`.
  No handler calls `access::check_read` / `check_write` or reads
  `server_user_grant`; they only use `RequirePermission<…>` (global catalog).
  `cases.rs:125-149` takes `serverConfigId` from the request body;
  `actions.rs` dispatches ban/kick/mute to `case.serverConfigId`.
- **Why:** a moderator granted only on server A can open a case against
  server B and ban/kick any UID there with B's stored credentials, and can
  read every server's cases, reports and notes. This breaks the grant model
  that `check_write` enforces everywhere else.
- **Fix:** resolve the server from the body or the stored case and call
  `check_write` before any mutation or dispatch, `check_read` for reads.
  Filter list queries by the caller's grants (admins unfiltered).

### H2. Widget admin writes skip the server grant

- **Where:** `widgets/admin.rs` create (`:223`), patch (`:266`), delete
  (`:313`), regenerate-token (`:352`). They take `RequireModerator(_user)`
  and never use the user. List/detail do call `caller_can_view`.
- **Why:** a moderator without a grant on server B can mint a widget for B
  and receive its token, which exposes B's live channel tree and client list
  on the public widget endpoints and WS topic. They can also rotate or delete
  any widget by id, breaking other servers' embeds.
- **Fix:** `check_write(req.server_config_id)` on create and
  `check_write(existing.serverConfigId)` on patch/delete/regenerate (and on
  the new id if patch changes the server).

### H3. Music runtime HTTP API is unauthenticated on all interfaces

- **Where:** `deploy/kube/ts6-manager.yaml:181` `--listen 0.0.0.0:3002`
  under `hostNetwork: true` (`:84`). Routes in
  `crates/voice/src/runtime_http.rs:55-63` (`/v1/bots`, `/command`,
  `/v1/settings`, `/v1/bug-report-context`, `/v1/mutate`, `/v1/store`) have
  no auth.
- **Why:** anyone who can reach host port 3002 can spawn bots, play any
  URL or file path, change the YouTube key / cookie path, and read the log
  tail. It bypasses every manager-side gate. Real exposure depends on the
  host firewall (not verified here, and not changed here). The sidecar
  already binds `127.0.0.1:7080` for this exact reason (`:239-241`).
- **Fix (manifest only, not a host change):** listen on `127.0.0.1:3002`.
  The manager already calls `http://127.0.0.1:3002` (`:137`) and both probes
  are loopback (`:216`, `:225`). Optionally add a shared-secret header.
  Not changed on this branch, because it touches the Contabo pod spec and
  needs a deploy owner's +1.

### H4. SSRF gate and library jail cover only `POST /play`

- **Where:** the `6e40ec5` gate lives in `routes/music_bots/audio_control.rs`.
  These write paths store sources with no `is_url_allowed` and no
  `confine_library_path`: `queue.rs:47` enqueue, `playlists.rs:197`
  add_track, `library.rs:81` add, `radio_stations.rs:74/149`, and TeamSpeak
  chat `!play` / `!radio` (`crates/voice/src/chat.rs:467`, only an `is_url`
  prefix test). At playback the runtime discards `MUSIC_DIR`
  (`crates/voice/src/bin/ts6-manager-music.rs:98`, `let _ = ...`) and passes
  `LibraryPath` to `ffmpeg -i` unchanged (`crates/voice/src/audio.rs:203`).
- **Why:** any TeamSpeak user in the bot's channel, with no panel account,
  can make the host GET `http://169.254.169.254/…` or `http://127.0.0.1:…`
  through yt-dlp/ffmpeg/reqwest, and can use the chat replies as a port
  scanner. Panel users can store absolute file paths (`/dev/urandom`, data
  dir files) that ffmpeg then opens.
- **Fix:** enforce both checks in the music runtime where every path
  converges (`source_to_spec` / pipeline start): SSRF-check URLs, join
  library paths onto `MUSIC_DIR`, canonicalize, require `starts_with(root)`.
  Keep the route-level gate as an early error for the UI.

### H5. The `/play` gate is bypassable after it passes

- **Where:** `audio_control.rs:202` forwards the raw `url` string, not the
  normalized `target.url`. Fetchers then do their own DNS and redirects:
  yt-dlp (`source/url.rs`), the ICY `reqwest::Client` with default redirect
  policy (`source/icy.rs:54`), and ffmpeg with no `-tls_verify 1`, default
  redirects and HLS segment fetches (`source/ffmpeg.rs:36-52`).
- **Why:** `http://evil.example\@127.0.0.1/a.mp3` parses as host
  `evil.example` in the WHATWG gate but as `127.0.0.1` in ffmpeg/Python
  (medium confidence on the exact parser behaviour). A public URL can 302 to
  metadata, DNS can rebind, and an HLS playlist can list internal segments.
  The code comment's claim that "TLS binds the name" is false while ffmpeg
  runs with `tls_verify=0`. A stored value starting with `-` was also read as
  a yt-dlp option (`--exec`, `--config-locations`).
- **Fix:** forward `target.url.as_str()`. Copy the sidecar's `tls_args_for`
  into `apply_ffmpeg_input_args`. ICY client: `redirect(Policy::none())` +
  `resolve_to_addrs`. For ffmpeg/yt-dlp, route through the sidecar-style pin
  proxy or accept egress filtering as the real control.
  **Done here:** `--` before the URL in both yt-dlp invocations.

## Medium

- **M1 (fixed). Keyed rate limiters never evict.** governor 0.6.3 only
  drops keys on `retain_recent()`, which nothing called. Auth, setup, widget
  and public moderation limiters grew by one entry per source IP forever,
  and the widget per-token limiter keyed on the attacker-chosen path segment.
  Fix: 60 s sweep for all six limiters; token keys over 64 bytes share one
  bucket; corrected the wrong module comment in `web/rate_limit.rs`.
- **M2 (fixed). Bot control task panic on multibyte radio URLs.**
  `source/select.rs:67` sliced at a fixed byte offset; reachable via chat
  `!play https://aéicecast.example/`.
- **M3. Admin sessions endpoint returns live refresh tokens.**
  `routes/users.rs:692` copies `replacedBy` (plaintext successor token) into
  `AdminSession` (`shared/src/admin.rs:78`). An admin, or any XSS in the admin
  UI, can lift other users' live refresh tokens. Tokens are also stored
  plaintext (`repos/refresh_tokens.rs:23`). Fix: drop `replaced_by` from the
  wire (return `rotated: bool`), store SHA-256 of `token` / `replacedBy`.
- **M4. Any viewer can drive music bots and pick an identity file.**
  `routes/music_bots/bots.rs` uses `RequireAuth` only; `identity_path` from
  the request (`:133`) is used as-is and created if missing; `server_addr` is
  unchecked. Fix: ignore client `identity_path`, require moderator + grant,
  restrict `server_addr` to a configured `server_connection`.
- **M5. SSH keepalive timeout desyncs responses.**
  `sshbridge/transport.rs:618-653`: a `whoami` timeout increments a counter
  (threshold 3) but leaves the late reply on the wire; the next
  `execute_one` consumes it as its own. Every later caller gets the previous
  command's result (including `use sid=`), and the audit log records the
  wrong outcome until reconnect. Fix: treat any keepalive timeout as
  `Reconnect`, or drain to a tagged marker.
- **M6. Server PATCH doesn't rebuild cached clients.** `routes/servers.rs`
  `patch_server` never calls `state.control.remove(id)` /
  `state.webquery.remove(id)` (only delete does, `:233-234`). Rotating a
  leaked API key / SSH password, or correcting a TOFU fingerprint that pinned
  a MitM, has no effect until restart. Fix: invalidate both pools on success.
- **M7. SSRF blocklist gaps.** `crates/ts6-ssrf/src/ranges.rs` misses
  `100.64.0.0/10` (CGNAT, Alibaba metadata `100.100.100.200`, Tailscale),
  `198.18.0.0/15`, `192.0.0.0/24`, multicast/reserved, NAT64 `64:ff9b::/96`,
  6to4 `2002::/16` with embedded private v4, `::/96`, `fec0::/10`, `ff00::/8`.
- **M8. Media sidecar HTTPS and HLS are not pinned.** `ts6-media-sidecar`
  `control.rs:335` passes HTTPS straight to ffmpeg; `pipeline.rs` sets
  `-tls_verify 1` but no `-protocol_whitelist` / redirect limit, and nested
  manifest URLs bypass the plaintext pin proxy. (Medium-high confidence.)
- **M9. `NODE_ENV` fails open to the public dev JWT secret.**
  `config.rs:39-43,213-227`: anything but exact `production` uses
  `dev-secret-change-me-in-production`; short secrets only warn;
  `ENCRYPTION_KEY` falls back to the JWT secret. Shipped Containerfile/Quadlet
  set `production`, so Contabo is not affected, but a bare-binary deploy
  would accept forged admin tokens. Fix: refuse to boot on the placeholder
  unless an explicit dev flag is set.
- **M10. WebSocket principals are never re-checked.**
  `auth/ws_handshake.rs:63`, `ws/session.rs:56-66`: disabled/demoted users
  and expired tokens keep receiving subscribed topics (including admin-only
  `logs`) for the life of the socket. Fix: close on token `exp`, re-read
  role/enabled on subscribe and on the ping tick.

## Low

- **L1. Rapid ↑/↓ reorder uses a stale sibling chain** (`ui/pages/channels.rs`
  `on_reorder`): no in-flight guard, so a second click computes
  `channel_order` from the pre-reload tree. Worst case is an unexpected
  position, not data loss. Fix: disable ↑/↓ while a reorder is pending.
- **L2. Clients page channel picker never refreshes** after channel
  create/rename/delete (no `server:{id}:channels` subscription), and a failed
  channel fetch shows "No other channel" instead of an error.
- **L3. Reorder with a broken chain** can send `siblings[idx-1].channel_order`
  pointing at a cid outside the parent (`sibling_move_order`); TS rejects it,
  so it surfaces as a failure toast only.
- **L4. Refresh rotation vs reuse revocation race** (`auth/refresh.rs:183-198`
  vs `:241-248`): CAS and insert are separate statements, so revocation
  between them can leave an orphan live token. Fix: one transaction.
- **L5. Only the first `X-Forwarded-For` header line is read**
  (`web/proxy.rs:99,139`); proxies that add a separate line let clients
  choose their rate-limit key. Fix: `get_all()` and join.
- **L6. Login timing reveals valid usernames** (`auth/routes.rs:87-93`):
  missing/disabled users skip Argon2. Fix: verify against a dummy hash.
- **L7. `PUT /api/auth/password` is not rate limited** (`auth/routes.rs:58`).
- **L8. Access tokens in URLs** (SSE `?token=`, WS handshake) end up in proxy
  access logs; default access lifetime is 4 h vs the spec's 15 m.
- **L9. Flows and run history readable across servers** by any viewer
  (`flow/routes.rs:473-606,955,997`).
- **L10. WebQuery client follows redirects with `x-api-key` attached**
  (`webquery/mod.rs:212-220`; reqwest strips `Authorization`, not custom
  headers) and builds the base URL from an unvalidated host string. The same
  host string lets the pre-setup probe (`routes/setup.rs:266`) fetch an
  arbitrary path. Fix: `Policy::none()`, parse host with `url::Host::parse`.
- **L11. HTTPS webhooks fall back to unpinned system DNS** when validation-
  time lookup fails (`ts6-ssrf/src/lib.rs:172-207`,
  `flow/dispatch.rs:857-868`), and the webhook client honours
  `HTTP(S)_PROXY` (`dispatch.rs:808`; add `.no_proxy()`).
- **L12. Notify registration after reconnect runs without `use sid=`**
  (`ws/server_notify.rs:333-345`), bypassing `sid_gate`. Medium confidence;
  depends on TS6 requiring `use` first.
- **L13. SSH audit stores `clientmove` `cpw` in plaintext**
  (`sshbridge/audit.rs:333` redacts by suffix; `cpw` doesn't match).
- **L14. Concurrent first requests build duplicate control backends**
  (`control/mod.rs:682-692`), each with its own TOFU verifier.
- **L15. TOFU persistence is best-effort, and PATCH with an empty
  fingerprint silently re-arms TOFU** (`sshbridge/tofu.rs:107-125`,
  `routes/servers.rs:169-184`).
- **L16. voice-rt renice decays**: tokio blocking-pool threads are also named
  `voice-rt`, are created lazily after the one-shot host renice, and run at
  nice 0 (still pinned to 0-1). A music restart also drops the renice until
  `update.sh` runs again. Doc/runbook note; no host change proposed.
- **L17. Concurrent yt-dlp processes share one `--cookies` file** and write
  it back on exit, which can corrupt the uploaded cookie jar.
- **L18. Predictable `/tmp/ts6-yt-resolver-{pid}.py`** written with
  symlink-following `fs::write` (`music-bot-audio/src/resolver.rs:410`).
- **L19. Soft-pin script only refuses literal `0-1` spellings** for the music
  HostConfig and does not warn when any music cpuset is set under packing B.
